# Skedula 제작 계획

첫 이정표는 MacBook에서 ‘오늘’ 화면을 열고 실제 하루를 계획해 보는 것이다. 아래 순서는 작업의 선후 관계를 나타낸다. 후속 기능과 배포 범위는 첫 사용 결과를 보고 정한다.

## 진행 방식

- Codex가 조사, 설계 초안, 구현, 검증을 맡는다. 핵심 흐름·페이지 역할·배치·추천 순서에 대한 선택이 필요하면 같은 하루를 적용한 대안과 추천 이유를 준비해 사용자와 논의한다.
- 작업이 끝나면 해당 항목을 `[x]`로 바꾸고 옆에 결과를 확인할 수 있는 문서, 시안, 코드 또는 검증 기록을 연결한다. 검토 대기 중인 항목은 열린 채로 둔다.
- 설계의 기준은 [제품 구상](product-concept.md)이다. 합의·제안·미결 사항과 기술 실험의 결론은 그 문서에 반영하고, 이 파일에서는 제작 진척을 추적한다.

## 1. 출발점과 레퍼런스

- [x] 기존 제품 구상에서 첫 대상(macOS), 첫 화면(오늘), 마감과 작업 시간의 차이를 확인했다. [제품 구상](product-concept.md)
- [ ] 기존 앱을 실행하고 일정 생성부터 재실행까지 따라간다. 화면·코드·저장 데이터에서 재사용할 부분과 교체 후보를 기록한다.
- [ ] 캘린더, 할 일 관리, 시간 배정 도구에서 각각 실제 화면 사례를 찾는다. 출처 링크와 함께 ‘빈 시간 찾기’, ‘마감 없는 중요 과제 발견’, ‘할 일에 시간 배정’에 필요한 행동을 비교하고 Skedula에서 시험할 방식을 고른다.

## 2. 첫 사용 시나리오와 구현 범위

- [ ] 같은 예시 하루를 만든다. 15시 치과, 17시까지 회신, 다음 달 마감인 중요 문서, 마감 없는 포트폴리오, 버킷리스트의 사진 산책을 넣는다. 추천 순서를 보기 전에 사용자가 먼저 챙기고 싶은 항목과 이유를 확인한다.
- [ ] 위 사례로 첫 버전에서 할 수 있어야 할 일을 합의한다. 검토할 흐름은 빈 시간 확인 → 오늘 할 일 선택 → 필요하면 작업 시간 배정 → 완료다. 버킷리스트를 어디에서 꺼낼지와 첫 버전에서 미룰 범위도 기록한다.

## 3. 화면을 연결하는 UI 설계

- [ ] 오늘·할 일·버킷리스트의 역할과 이동 경로를 그린다. 한 항목을 선택·배정·이동·완료하거나 배정을 취소할 때 각 화면에서 무엇이 바뀌는지 정리한다.
- [ ] 같은 하루로 ‘마감 임박과 중요한 일을 나눈 목록’과 ‘이유를 붙인 단일 목록’ 시안을 비교한다. 급하면서 중요한 항목도 추가해 표시 위치와 순서를 설명하고 사용자와 방향을 정한다.
- [ ] 합의한 시안을 클릭 가능한 프로토타입으로 연결한다. MacBook 크기에서 회신 마감을 17시로 유지한 채 작업 시간을 11시 30분으로 잡고 옮겨 본다. 빈 목록, 긴 제목, 일정 겹침, 키보드 조작도 확인한다.

## 4. 아키텍처와 기술 검증

- [ ] 일정, 할 일, 마감, 작업 시간, 오늘 선택, 버킷리스트의 관계를 설계한다. 화면 간에 같은 항목을 식별하는 방법과 기존 SQLite 데이터의 호환 여부를 정한다.
- [ ] UI, 계획·추천 규칙, 저장소의 책임을 나눈다. 예시 하루를 화면 없이도 정렬하고 각 추천 이유를 확인할 수 있는지 검토한다.
- [ ] 기존 코드와 Python + PySide6 후보로 핵심 조작의 구현 비용을 비교한다. macOS에서 시간 배정·저장·재실행을 작게 시험하고 Windows 배포에 영향을 주는 의존성을 확인한 뒤 기술을 결정한다.

## 5. ‘오늘’ 화면 구현과 사용 검증

- [ ] 합의한 흐름 하나를 UI부터 저장까지 연결한다. 예시 회신을 오늘 할 일로 고르고 시간을 배정한 뒤 재실행해 마감과 작업 시간이 각각 복원되는지 확인한다.
- [ ] 합의한 나머지 흐름과 추천 이유를 구현한다. 완료·배정 취소 등 상태 변화가 관련 화면에 일관되게 반영되는지 확인한다.
- [ ] 사용자가 예시 하루와 자신의 실제 하루를 각각 계획해 본다. 놓친 중요 과제, 예상과 다른 추천 순서, 막힌 조작을 기록한다. 우선 수정할 문제를 고쳐 같은 사례로 다시 확인한다.

## 6. 후속 범위와 첫 배포

- [ ] 사용 검증 결과로 할 일 관리·버킷리스트 등 후속 범위와 순서를 합의한다. 선택한 기능마다 화면 흐름 설계 → 구현 → 사용 검증을 반복한다.
- [ ] 첫 배포 범위가 충족되면 macOS 설치본을 만들고 깨끗한 환경에서 설치·실행·저장·재실행을 확인한다. 지원 환경, 설치 방법, 알려진 제약을 기록하고 Windows 검증 시점을 정한다.

## 첫 피드백 세션

- [x] [오늘 테스트 화면](../prototype/today.html)에서 예시 회신을 오늘로 고르고 11시 30분에 배정했다. 17시 마감 유지, 새로고침 후 배정 복원, 완료 시 시간표 표시 갱신을 Chrome에서 확인했다.
- [ ] 실제 창을 사용한 피드백을 받아 배치와 첫 구현 범위를 합의한다.
- [x] 첫 피드백을 반영해 [시간표와 사이드바](../prototype/today.html)를 수정했다. 24시간 눈금, 30분 예약 높이, 탭별 목록, 드래그 배정 후 재실행을 확인했다.
- [x] 세 차례 사용성 점검을 반영했다. 고정 문구였던 중요도·마감을 편집 가능하게 했고, 작업 시간 변경 시 원래 배정과 겹치는 일정을 표시했다. 좁은 목록에서는 아이콘을 다음 줄로 옮기고 편집 후 키보드 초점을 복원했다. Chrome에서 정렬·저장·겹침 안내·좁은 목록 너비와 기존 드래그 배정을 확인했다.
- [x] 작업 시간 입력에 관한 웹 레퍼런스 세 가지를 조사해 [조작 가능한 비교 창](../prototype/time-studies.html)에 원문 링크와 예시를 놓았다. 각 방식의 선택과 배정 표시를 확인했다.

## 반복 기능 점검

- 로컬 Chrome과 Node.js가 설치된 Mac에서 `cd qa && npm ci && npm test`로 시작한다. Playwright가 독립된 브라우저에서 할 일 선택·편집·배정·완료·재실행을 검증한다. 실패한 화면은 qa/test-results에 저장된다.
- 매 회차 계획 문서에서 아직 검증하지 않은 사용자 행동이나 최근 바뀐 흐름 하나를 선정한다. 정상 동작과 실패하기 쉬운 사례를 직접 조작하고, 재현되는 문제는 수정 전 실패와 수정 후 통과를 확인한다. 유용한 새 회귀 사례는 테스트로 남긴다.
- 확인한 범위와 남은 문제를 근거와 함께 기록한다. 핵심 경험·화면 배치·우선순위에 관한 새 결정은 구상 문서에 제안으로 모으고, 독립적으로 진행할 수 있는 검증을 이어간다.
- [x] 첫 회차에서 중요도·마감·오늘 선택의 저장을 확인했다. 완료한 작업의 시간표 블록이 빈 편집 창을 여는 문제를 수정하고 재실행 후 완료 상태를 검증했다.
- [x] [다섯 가지 계획 기능 시안](product-concept.md#일주일을-계획하는-기능-시안)을 구현했다. Chrome에서 주간 약속 생성·이동 시간·다음 주 반복·편집과 메모함 → 버킷리스트 → 오늘 선택을 검증했다.
- [x] 오늘·주간·할 일·메모함·버킷리스트를 같은 1160×820 창에서 수정 전후 비교했다. 사이드바 대비와 중복 제목을 줄이고, 주간 일정의 시각과 이름을 정렬했다.

### 한 세션 안에서 검증하는 방식

자율 점검을 요청받으면 같은 세션에서 3~4회 연속으로 진행한다. 회차마다 서로 다른 사용자 행동을 선택하고 재현·수정·재검증 결과를 적는다. 정상인 경우 확인한 경계를 기록한다. 세션 안에서 마치기 어려우면 재현 방법, 남은 문제와 다음 검증 지점을 인계한다.

| 2026-11-25 회차 | 시나리오 | 결과 |
| --- | --- | --- |
| 1 | 오전 작업과 오후 약속이 있는 날을 월간에서 열기 | 약속이 작업보다 먼저 보이는 오류를 재현했다. 주간과 월간이 같은 시각순 목록을 사용하도록 수정하고 재검증했다. |
| 2 | 1월 1일 00:10 약속에 30분 이동을 배정하기 | 주간에서 12월 31일 23:40–24:00과 1월 1일 00:00–00:10을 확인했다. 다음 달 보기에도 약속이 표시됐다. |
| 3 | 월간 날짜에서 Enter로 주간을 열고 약속 추가하기 | 화면 전환 후 키보드 초점이 사라지는 문제를 재현했다. 선택한 날짜의 추가 버튼으로 초점을 옮겨 날짜를 다시 찾지 않고 입력할 수 있게 했다. |

새 사례 3개를 포함해 Chrome 테스트 10개가 통과했다.
